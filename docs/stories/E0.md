# E0 Foundations, compatibility and approvals

**Goal:** Settle the technical and organisational unknowns that could block the whole project before feature work starts: a compatible version matrix, working environments, and the approval process started.

**Depends on:** None

## E0-S1 Version compatibility spike

**Status:** Done (2026-11-23) on `@a2ui/angular` 0.14.0 + Angular 21.2 + `@copilotkit/angular` 0.3.1. The 0.14.0 pin conflicted with CopilotKit 0.6.0; the decision is recorded. Pending confirmation against the real internal library.

**User story:** As a developer, I want to confirm our internal component library, @a2ui/angular and @copilotkit/angular work on the same Angular version, so that we don't discover a blocking peer-dependency conflict mid-build.

**Description:** Create a throwaway Angular app on the internal library's Angular version. Install @a2ui/angular, @a2ui/web_core, @copilotkit/angular and @angular/cdk. Render one internal Card inside an A2UI surface from a hand-written spec.

**Acceptance criteria**

- [x] A version matrix (Angular, internal library, A2UI, CopilotKit, CDK, Node) is documented in the repo README.
- [x] npm install completes with no peer-dependency errors and no --force or --legacy-peer-deps.
- [x] One internal-library component renders from a hand-written A2UI JSON spec in the browser.
- [x] If versions conflict, the conflict and the options (upgrade, wait, fork adapter) are written up and a decision is recorded.

## E0-S2 Internal LLM capability check

**Status:** To do

**User story:** As a tech lead, I want to verify the internal AI platform supports tool calling and JSON-schema-constrained output, so that we know the agent can reliably produce valid A2UI.

**Description:** Call the internal model endpoint with a sample tool definition and a JSON schema for a small A2UI spec. Run 50 prompts and measure the valid-output rate and latency.

**Acceptance criteria**

- [ ] Tool calling works: the model returns a correctly formatted tool call for at least 9 of 10 test prompts.
- [ ] With schema-constrained output enabled, at least 95% of 50 responses parse and validate against the schema.
- [ ] p50 and p95 latency for a 1-2 KB spec are recorded.
- [ ] Whether the endpoint is OpenAI-compatible (for the CopilotKit runtime) is confirmed.
- [ ] Results and the recommended model are documented.

## E0-S3 Repository, CI and environments

**Status:** In progress (2026-11-23). Repo, packages, lint, tests, CI workflow and local compose are in place. Still open: first CI run on GitHub, branch protection, a shared dev environment, and the secret manager.

**User story:** As a developer, I want a monorepo with CI and dev/test environments, so that all later stories have somewhere to land.

**Description:** Set up the repo structure (Angular app, catalog library, agent service, domain services, MCP server), linting, unit-test runners and a CI pipeline. Provision a dev environment with access to the internal LLM endpoint.

**Acceptance criteria**

- [x] Repo contains the agreed packages with a README describing each.
- [ ] CI runs lint, unit tests and build on every pull request and blocks merge on failure.
- [ ] Dev environment is deployable from main with one command or pipeline.
- [ ] (Partly: no secrets in repo, env vars only; secret manager not wired yet) Secrets (LLM credentials, service tokens) come from the company secret manager, never from the repo.
