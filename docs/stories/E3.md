# E3 Angular app shell and transport layer

**Goal:** Build the Angular host that renders A2UI surfaces and talks to the backend only through a transport interface, so the later MCP App is a swap rather than a rewrite.

**Depends on:** E1

## E3-S1 App shell and authentication

**Status:** Done for the MVP (2026-11-25), authentication deferred. Shell in `frontend/src/app/shell/`, layout wrapper `ui-app-layout` and `ui-nav-link` in `@app/ui`. The two SSO criteria are deferred, not dropped: they return before any real user data (see `docs/decisions.md`).

**User story:** As a user, I want to sign in with my company identity and land on the app, so that my data is protected and tied to me.

**Description:** Angular shell with routing, layout regions (main surface, optional chat panel) and SSO through the company identity provider. Tokens are attached to backend calls by an interceptor.

**Acceptance criteria**

- [ ] *(Deferred for the MVP.)* Unauthenticated users are redirected to SSO and returned to the requested page after sign-in.
- [ ] *(Deferred for the MVP.)* Access tokens are never stored in localStorage; the approach follows company security guidance.
- [x] The shell has a main A2UI surface region and a collapsible panel reserved for chat.
- [x] Shell components use the internal library's layout and theme. *(Through `@app/ui`: `ui-app-layout`, `ui-nav-link`, Material stand-in today.)*

## E3-S2 AgentTransport interface

**Status:** Done (2026-11-25). `frontend/src/app/transport/`: `AgentTransport` (abstract class used as the DI token), `MockTransport`, recordings in `recordings/*.json`. Chosen in `app.config.ts` with `provideAgentTransport(...)`. The assistant panel has an MVP prompt box that sends through it (E5-S5 replaces it with the CopilotKit chat).

**User story:** As a developer, I want one interface for all agent communication, so that web and MCP delivery use the same app code.

**Description:** Define AgentTransport with an incoming stream of A2UI messages, a method to send user actions and prompts, and connection state. Provide it through Angular DI so the implementation is chosen at bootstrap.

**Acceptance criteria**

- [x] No component or service outside the transport layer calls HttpClient, fetch, EventSource or postMessage for agent traffic. *(Enforced by `transport-boundary.spec.ts`, which scans `src/`.)*
- [x] The interface exposes: incoming messages stream, sendAction, sendPrompt and connection status.
- [x] A MockTransport replays recorded A2UI message files for tests and demos.
- [x] Swapping the implementation requires changing one provider line only.

## E3-S3 HTTP/streaming transport

**Status:** Done (2026-11-25), against a fake server in tests; it gets a real one with the agent service (E5-S1). `frontend/src/app/transport/http-transport.ts` and `sse.ts`; protocol in [docs/agent-protocol.md](../agent-protocol.md). The app still runs on `MockTransport`; switching is the one provider line in `app.config.ts`.

**User story:** As a user, I want the UI to stream in as it is generated, so that I see progress instead of a blank screen.

**Description:** Implement HttpTransport over SSE or WebSocket to the backend (the CopilotKit runtime once E5 lands), with reconnection and backoff.

**Acceptance criteria**

- [x] A2UI messages render progressively as they arrive.
- [x] On connection loss the transport retries with exponential backoff and shows a non-blocking banner.
- [x] Messages arriving after a reconnect do not duplicate already-rendered components.
- [x] Network errors surface as a user-readable message, never a raw stack trace.

## E3-S4 A2UI surface host and action router

**User story:** As a developer, I want a host component that renders A2UI surfaces and routes their actions, so that screens and actions are wired consistently.

**Description:** Wrap the @a2ui/angular surface with the E1 catalog, a validation step (E1-S4 schema) and an action router mapping action names to allow-listed handlers.

**Acceptance criteria**
