# E3 Angular app shell and transport layer

**Goal:** Build the Angular host that renders A2UI surfaces and talks to the backend only through a transport interface, so the later MCP App is a swap rather than a rewrite.

**Depends on:** E1

## E3-S1 App shell and authentication

**Status:** To do

**User story:** As a user, I want to sign in with my company identity and land on the app, so that my data is protected and tied to me.

**Description:** Angular shell with routing, layout regions (main surface, optional chat panel) and SSO through the company identity provider. Tokens are attached to backend calls by an interceptor.

**Acceptance criteria**

- [ ] Unauthenticated users are redirected to SSO and returned to the requested page after sign-in.
- [ ] Access tokens are never stored in localStorage; the approach follows company security guidance.
- [ ] The shell has a main A2UI surface region and a collapsible panel reserved for chat.
- [ ] Shell components use the internal library's layout and theme.

## E3-S2 AgentTransport interface

**Status:** To do

**User story:** As a developer, I want one interface for all agent communication, so that web and MCP delivery use the same app code.

**Description:** Define AgentTransport with an incoming stream of A2UI messages, a method to send user actions and prompts, and connection state. Provide it through Angular DI so the implementation is chosen at bootstrap.

**Acceptance criteria**

- [ ] No component or service outside the transport layer calls HttpClient, fetch, EventSource or postMessage for agent traffic.
- [ ] The interface exposes: incoming messages stream, sendAction, sendPrompt and connection status.
- [ ] A MockTransport replays recorded A2UI message files for tests and demos.
- [ ] Swapping the implementation requires changing one provider line only.

## E3-S3 HTTP/streaming transport

**Status:** To do

**User story:** As a user, I want the UI to stream in as it is generated, so that I see progress instead of a blank screen.

**Description:** Implement HttpTransport over SSE or WebSocket to the backend (the CopilotKit runtime once E5 lands), with reconnection and backoff.

**Acceptance criteria**

- [ ] A2UI messages render progressively as they arrive.
- [ ] On connection loss the transport retries with exponential backoff and shows a non-blocking banner.
- [ ] Messages arriving after a reconnect do not duplicate already-rendered components.
- [ ] Network errors surface as a user-readable message, never a raw stack trace.

## E3-S4 A2UI surface host and action router

**Status:** To do

**User story:** As a developer, I want a host component that renders A2UI surfaces and routes their actions, so that screens and actions are wired consistently.

**Description:** Wrap the @a2ui/angular surface with the E1 catalog, a validation step (E1-S4 schema) and an action router mapping action names to allow-listed handlers.

**Acceptance criteria**

- [ ] Specs are validated before rendering; invalid specs show a fallback card and log the error.
- [ ] Only action names on the allow-list are handled; unknown actions are ignored and logged.
- [ ] Multiple surfaces (for example main view and a side widget) can render at once with independent state.
- [ ] A loading skeleton from the internal library shows while a surface is building.
