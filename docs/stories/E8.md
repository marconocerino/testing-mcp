# E8 MCP App packaging and Copilot integration

**Goal:** Ship the same app inside Copilot as an MCP App: Copilot's model calls our MCP tools, generate_view calls the internal agent, and our Angular bundle renders the A2UI in the Copilot iframe.

**Depends on:** E5, E7

## E8-S1 MCP server with domain and view tools

**Status:** To do

**User story:** As a developer, I want an MCP server exposing our tools and UI resource, so that MCP hosts can use the app.

**Description:** Build the server with the official MCP SDK and MCP Apps extension. Expose generate_view plus the read and preview tools from E2-S5, and register the ui:// resource linked from the UI tools via _meta.ui.resourceUri.

**Acceptance criteria**

- [ ] Tools list and descriptions come from the shared definitions (E2-S5), not duplicated.
- [ ] generate_view calls the E5 agent and returns the A2UI spec in structured content for the widget, plus a short non-sensitive text summary for the host model.
- [ ] The UI resource is served with mime type text/html;profile=mcp-app, and CSP and permissions are declared on the resource.
- [ ] Without MCP Apps support in the host, tools still return useful text.
- [ ] No tool can place orders (same rule as E7-S1).

## E8-S2 Single-file Angular bundle

**Status:** To do

**User story:** As a developer, I want the renderer and catalog built as one HTML file, so that it can be served as an MCP App resource.

**Description:** A separate build target that includes the A2UI renderer, E1 catalog and internal library, and inlines JS and CSS. Excludes CopilotKit and the chat UI.

**Acceptance criteria**

- [ ] Build produces a single HTML file with no external script dependencies, or every external domain (fonts, assets) is declared in the resource CSP.
- [ ] Bundle size is reported in CI with an agreed budget.
- [ ] Rendering in the bundle matches the web app for every E4 sample spec (visual regression).
- [ ] The bundle works without cookies or localStorage.

## E8-S3 McpAppTransport

**Status:** To do

**User story:** As a developer, I want an AgentTransport implementation over the MCP Apps bridge, so that the same app code runs inside the host.

**Acceptance criteria**

- [ ] Implements the E3-S2 interface using the MCP Apps bridge (initialize handshake, tool results in, tool calls out).
- [ ] Selected by one provider line in the bundle's bootstrap; no other code changes.
- [ ] User actions in the widget call app-visible tools through the bridge; disallowed actions are blocked.
- [ ] Handles host resize, theme and teardown events.

## E8-S4 Authentication for MCP

**Status:** To do

**User story:** As a user, I want Copilot to access only my data, so that using the app through Copilot is as secure as the web app.

**Acceptance criteria**

- [ ] The MCP server uses OAuth with the company identity provider, as required by the target host.
- [ ] Every tool call resolves to the signed-in user; calls without a valid user are rejected.
- [ ] Tokens are never passed to the widget iframe or the host model.
- [ ] Approved by security (E7-S6).

## E8-S5 Local host testing

**Status:** To do

**User story:** As a developer, I want to test the MCP App in local hosts with mock data, so that we can iterate without tenant approval.

**Acceptance criteria**

- [ ] The app works end to end in at least two hosts (for example the ext-apps reference host and VS Code or Goose) using mock data only.
- [ ] A test script covers: open dashboard, generate a custom view, open a pre-filled OrderTicket.
- [ ] Host-specific differences found are documented with workarounds.

## E8-S6 Microsoft 365 Copilot deployment

**Status:** To do

**User story:** As a product owner, I want the app available in our company Copilot, so that users can reach it where they already work.

**Description:** Package the MCP server as a Copilot agent/plugin, deploy to a dev or sandbox tenant first, then go through the admin approval process identified in E0-S4.

**Acceptance criteria**

- [ ] Works end to end in a dev or sandbox tenant with mock data.
- [ ] The supported MCP Apps capabilities in Copilot are checked, and gaps are handled or documented.
- [ ] Security, compliance and M365 admin approvals are recorded before production rollout.
- [ ] Rolled out to a pilot group first, with a feedback channel and rollback plan.
