# E6 Personalization and layout persistence

**Goal:** Let users save, manage and refine the views they generate. Saved layouts store component trees and bindings only, never financial data.

**Depends on:** E5

## E6-S1 Save a generated view

**Status:** To do

**User story:** As a user, I want to save a view I created, so that I can come back to it without asking again.

**Description:** A Save action on any generated surface stores its validated component tree, bindings, name, prompt version and catalog version per user.

**Acceptance criteria**

- [ ] Saved layouts contain only component structure and data bindings; no balances, transactions or prices are stored.
- [ ] The user names the view; names are unique per user.
- [ ] Saving revalidates the spec; invalid specs cannot be saved.
- [ ] Saved views are visible only to their owner.

## E6-S2 Load and manage saved views

**Status:** To do

**User story:** As a user, I want to list, open, rename, reorder and delete my saved views, so that I control my workspace.

**Acceptance criteria**

- [ ] Saved views appear in navigation in the user's chosen order.
- [ ] Opening a saved view renders it with fresh data and no LLM call.
- [ ] Rename and delete take effect immediately; delete asks for confirmation.
- [ ] Up to 20 saved views per user (limit configurable).

## E6-S3 Set a personal home view

**Status:** To do

**User story:** As a user, I want to choose which view opens first, so that the app starts where I work.

**Acceptance criteria**

- [ ] Any saved view or the default dashboard can be set as home.
- [ ] "Reset to default" restores the hand-authored dashboard as home.
- [ ] If the home view fails validation after a catalog upgrade, the default dashboard opens and the user is told why.

## E6-S4 Edit a saved view by conversation

**Status:** To do

**User story:** As a user, I want to change a saved view by asking ("move predictions to the top, drop the chart"), so that I can refine it without starting over.

**Acceptance criteria**

- [ ] The agent receives the current saved spec as context and returns a modified spec.
- [ ] The user previews the change and chooses save, save as new, or discard.
- [ ] The previous version can be restored (last 5 versions kept).

## E6-S5 Catalog upgrade migration

**Status:** To do

**User story:** As a developer, I want saved views checked when the catalog changes, so that upgrades don't break users' layouts.

**Acceptance criteria**

- [ ] A migration job validates all saved views against a new catalog version before release.
- [ ] Views needing changes are migrated automatically where a rule exists, or flagged.
- [ ] The release is blocked if more than an agreed percentage of saved views would break.
